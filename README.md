# Quality-control

An open workflow for deciding whether quality-control (QC) evidence is safe enough to change a released data product.

A QC flag is not yet a decision. The same evidence can justify deleting a value, withholding it for review, keeping it with a warning, or alerting maintenance. This repository tests those evidence-to-action rules before release, on station networks. It accompanies the manuscript "From quality-control flags to auditable actions in environmental station networks: redundancy depth, spatial quarantine, and selection-bias diagnostics".

It is a set of scripts, not an installable package.

## Try it in one minute

The worked example uses a small synthetic network, so it needs no licensed data:

```bash
python -m venv .venv
. .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python examples/quickstart.py
python -m pytest -q tests
```

It shows the four ideas of the workflow:

1. **Effective redundancy.** Stations reporting at 5, 10 and 20 minutes seldom share exact timestamps, so working neighbours look missing until references are aligned in time.
2. **False isolation.** A comparison with the median of its neighbours tolerates only `floor((m-1)/2)` failed neighbours. Beyond that, healthy data are quarantined.
3. **The guard.** Invalid neighbours are excluded, and the comparison abstains below a quorum of three healthy neighbours.
4. **The action.** A value that disagrees is quarantined, not deleted, and an audit record is written to `examples/output/audit_record.csv`.

## How the workflow fits together

| Step | What happens | Main code |
|---|---|---|
| 1. Data | Clean timestamps and units, fix the design and evaluation periods, choose stations | `src/06_run_qc_with_guarantees_v3.py` |
| 2. Evidence | Local rules give FAIL and SUSPECT flags; neighbours give spatial evidence | `src/06_...`, `scripts/neighbour_reference.py` |
| 3. Actions | Candidate rules map evidence to delete, quarantine, keep or alert | `scripts/13_spatial_quarantine_archive.py` |
| 4. Release tests | Availability, state-dependent removal, retention of high values, injected faults, loss scores | `scripts/11`, `12_operational_risk_analysis`, `13` |
| 5. Generalisation | Unused stations, spatial coherence, second network | `scripts/21` to `26`, DWD scripts `16` to `19` |

[docs/WORKFLOW.md](docs/WORKFLOW.md) explains each step, its inputs and outputs, and the terms used.

## Reproducing the manuscript

**Public part.** The DWD results can be regenerated by anyone from public data. See [docs/DWD_OPEN_REPRODUCTION.md](docs/DWD_OPEN_REPRODUCTION.md).

**Licensed part.** AVAMET raw records cannot be redistributed. Access may be requested from AVAMET (info@avamet.org), subject to its terms. With the file in place as `avamet_all.parquet`:

```bash
python scripts/validate_input.py --input avamet_all.parquet
python scripts/run_experiment.py --input avamet_all.parquet --workdir . --redraw-figures
```

Then follow the commands in [docs/WORKFLOW.md](docs/WORKFLOW.md). Station-level screening outputs stay local, because the candidates they list are unconfirmed.

**Reference outputs.** Aggregated results of the revision are in `paper_artifacts/revision_r1/`, and DWD audit tables in `paper_artifacts/dwd_open_demo/`.

## Settings

Defaults reproduce the revised manuscript for the evaluation sample. Settings are environment variables documented at the top of [scripts/neighbour_reference.py](scripts/neighbour_reference.py). The network pool needs `NB_MODE=pool`.

| Setting | Value |
|---|---|
| References requested, `K` | 5 |
| Quorum, `q` | 3 healthy references |
| Pressure threshold, `tau` | 8 hPa |
| Reference time tolerance | 14 minutes |
| Random seeds | fault tests 20260519 and 1-4; neighbour failure 20260628 (DWD +1000); independent stations 20261106 |

To reproduce the originally reviewed behaviour: `NB_MODE=orig NB_TOL_MIN=0 NB_QUORUM=2 NB_REFHEALTH=0`. See [CHANGELOG.md](CHANGELOG.md) for the corrections made during review. The reviewed version is the tag `ems-review-2026-07-07`.

## Limits

The operational benefit of pressure quarantine rests on injected faults. Purely spatial checks cannot protect against most references being biased together. Results are scoped to the reported networks, periods and fault definitions.
